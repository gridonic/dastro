# Localization (i18n)

Reference for the `i18n` block of `src/config/dastro.config.ts` and the locale helpers of `i18n()`.

## Options

| Option | Values | Default | Meaning |
|--------|--------|---------|---------|
| `defaultLocale` | a site locale | required | Locale without prefix in `prefix-except-default`; root redirect fallback in `prefix-always` |
| `locales` | site locales | required | All locales, in order |
| `routingStrategy` | `'prefix-except-default'` / `'prefix-always'` | required | Whether the default locale gets a prefix |
| `localePrefix` | `'language'` / `'locale'` | `'language'` | What the locale prefix is derived from |
| `languageFallbacks` | language → site locale | none | Root resolution: locale for a language without an exact match |
| `localeCookie` | cookie name | none | Root resolution: a valid cookie value wins |

## `localePrefix`

`'language'` (default) keeps the behaviour of every release before this option. `'locale'` is for sites with several locales of one language (`de_CH` and `de_DE`), which collide on `/de` in `'language'` mode.

| | `'language'` | `'locale'` |
|---|---|---|
| Locale prefix of `de_CH` | `/de` | `/de-ch` |
| Locale prefix of `en` | `/en` | `/en` |
| Prefix → locale | first locale starting with the prefix | exact match; `/de/…` is not a prefix of `de_CH` |
| Upper-case prefix (`/de-CH/…`) | not a prefix | 301 to `/de-ch/…`, query string kept |
| `<html lang>`, hreflang | `de` | `de-CH` (language tag) |

`localePrefix` is independent of `routingStrategy`: with `prefix-except-default` the default locale still has no prefix, and its home is `/`.

```ts
i18n: {
  locales: ['de_CH', 'fr_CH', 'en', 'de_DE'],
  defaultLocale: 'en',
  routingStrategy: 'prefix-always',
  localePrefix: 'locale',
}
```

Switching an existing site to `'locale'` changes every prefixed URL (`/de/…` → `/de-ch/…`). Dastro does not redirect the old URLs; add those redirects in the project.

## Helpers

From `i18n()` (`Astro.locals.dastro.i18n()` or `i18n(config)`). All follow `localePrefix`.

| Helper | `'language'` mode | `'locale'` mode | Use for |
|--------|-------------------|-----------------|---------|
| `localePrefix(locale)` | `de_CH` → `de` | `de_CH` → `de-ch` | Building URLs by hand, e.g. a home-URL fallback `/${localePrefix(locale)}` |
| `localeLangTag(locale)` | `de_CH` → `de` | `de_CH` → `de-CH` | `lang` attributes, hreflang, values sent to tracking or forms |
| `localeFromPrefix(prefix)` | `de` → first `de…` locale | `de-ch` → `de_CH`, `de` → `undefined` | Reading the locale of a path segment |
| `localePrefixMode` | `'language'` | `'locale'` | Branching on the mode |

Prefer `resolveRecordUrl(record, locale)` from `routing()` over hand-built URLs; it already uses `localePrefix`.

`normalizedIsoLocale(locale, keepVariant?)` is **deprecated**. It still works and ignores `localePrefix`, so in `'locale'` mode it returns the wrong prefix (`de` instead of `de-ch`). Replace it with `localePrefix` (URLs) or `localeLangTag` (language values).

## Root resolution

With `routingStrategy: 'prefix-always'`, a request to the site root `/` is redirected to a locale prefix. Nothing else is ever redirected by locale. First hit wins:

1. **Locale cookie**: the cookie named by `localeCookie`, if its value is a site locale (`de_CH`). An invalid value is ignored and not cleared.
2. **`Accept-Language`**, entries sorted by q-value (header order breaks ties; `*`, malformed entries and `q=0` are ignored). The most preferred language the site has a locale of decides the language. Within that language:
   1. **Exact pass**: an entry whose full tag equals a locale (`fr-FR` → `fr_FR`), even when a bare `fr` is listed before it.
   2. **Fallback pass**: the `languageFallbacks` entry of the language.
   3. The first locale of the language in `locales` order.
3. `defaultLocale`.

Both options are opt-in. Without them, the root redirects to the first locale of the visitor's language, else to the default locale, as before.

```ts
i18n: {
  locales: ['de_CH', 'fr_CH', 'it_CH', 'en', 'de_DE', 'fr_FR'],
  defaultLocale: 'en',
  routingStrategy: 'prefix-always',
  localePrefix: 'locale',
  languageFallbacks: { de: 'de_CH', fr: 'fr_CH' },
  localeCookie: 'locale',
}
```

| `Accept-Language` | Redirect | Step |
|---|---|---|
| `de-DE,de;q=0.9,en;q=0.8` | `/de-de/` | exact |
| `fr,fr-FR;q=0.8` | `/fr-fr/` | exact beats fallback |
| `de,en-US;q=0.7,en;q=0.3` | `/de-ch/` | fallback (`de` is preferred over `en`) |
| `de-AT` | `/de-ch/` | fallback |
| `it` | `/it-ch/` | first locale of the language |
| `ja`, none | `/en/` | default locale |

The redirect is a 302, keeps the query string (`/?utm_source=x` → `/en/?utm_source=x`) and is never cached: `Cache-Control: private, no-store`, no `Netlify-CDN-Cache-Control`. Every root request therefore reaches the server.

### `setLocaleCookie` (client)

Dastro only reads the locale cookie. Write it in the browser when the visitor picks a locale (page responses are cached, so the server cannot set it):

```ts
import { setLocaleCookie } from 'dastro/client';

setLocaleCookie('locale', 'de_CH'); // then navigate
setLocaleCookie('locale', 'de_CH', { maxAge: 60 * 60 * 24 * 30 }); // seconds
```

| Argument | Meaning |
|---|---|
| `cookieName` | The value of `i18n.localeCookie`. Client code cannot read the dastro config: share the name as a constant or pass it through a `data-` attribute |
| `locale` | A site locale as configured (`de_CH`), not a locale prefix or language tag |
| `options.maxAge` | Lifetime in seconds, default one year |

The cookie is written with `Path=/` and `SameSite=Lax`. It is read only at the root: a deep link into another locale is served as linked.
