# Localization (i18n)

Reference for the `i18n` block of `src/config/dastro.config.ts` and the locale helpers of `i18n()`.

## Options

| Option | Values | Default | Meaning |
|--------|--------|---------|---------|
| `defaultLocale` | a site locale | required | Locale without prefix in `prefix-except-default`; root redirect fallback in `prefix-always` |
| `locales` | site locales | required | All locales, in order |
| `routingStrategy` | `'prefix-except-default'` / `'prefix-always'` | required | Whether the default locale gets a prefix |
| `localePrefix` | `'language'` / `'locale'` | `'language'` | What the locale prefix is derived from |
| `xDefaultLocale` | a site locale | none | Emits an `x-default` hreflang alternate pointing at that locale |

## `localePrefix`

`'language'` (default) keeps the behaviour of every release before this option. `'locale'` is for sites with several locales of one language (`de_CH` and `de_DE`), which collide on `/de` in `'language'` mode.

| | `'language'` | `'locale'` |
|---|---|---|
| Locale prefix of `de_CH` | `/de` | `/de-ch` |
| Locale prefix of `en` | `/en` | `/en` |
| Prefix → locale | first locale starting with the prefix | exact match; `/de/…` is not a prefix of `de_CH` |
| Upper-case prefix (`/de-CH/…`) | not a prefix | 301 to `/de-ch/…`, query string kept |
| `<html lang>`, hreflang | `de` | `de-CH` (language tag) |

`localePrefix` is independent of `routingStrategy`: with `prefix-except-default` the default locale still has no prefix, and its home is `/`.

```ts
i18n: {
  locales: ['de_CH', 'fr_CH', 'en', 'de_DE'],
  defaultLocale: 'en',
  routingStrategy: 'prefix-always',
  localePrefix: 'locale',
}
```

Switching an existing site to `'locale'` changes every prefixed URL (`/de/…` → `/de-ch/…`). Dastro does not redirect the old URLs; add those redirects in the project.

## Helpers

From `i18n()` (`Astro.locals.dastro.i18n()` or `i18n(config)`). All follow `localePrefix`.

| Helper | `'language'` mode | `'locale'` mode | Use for |
|--------|-------------------|-----------------|---------|
| `localePrefix(locale)` | `de_CH` → `de` | `de_CH` → `de-ch` | Building URLs by hand, e.g. a home-URL fallback `/${localePrefix(locale)}` |
| `localeLangTag(locale)` | `de_CH` → `de` | `de_CH` → `de-CH` | `lang` attributes, hreflang, values sent to tracking or forms |
| `localeFromPrefix(prefix)` | `de` → first `de…` locale | `de-ch` → `de_CH`, `de` → `undefined` | Reading the locale of a path segment |
| `localePrefixMode` | `'language'` | `'locale'` | Branching on the mode |

Prefer `resolveRecordUrl(record, locale)` from `routing()` over hand-built URLs; it already uses `localePrefix`.

`normalizedIsoLocale(locale, keepVariant?)` is **deprecated**. It still works and ignores `localePrefix`, so in `'locale'` mode it returns the wrong prefix (`de` instead of `de-ch`). Replace it with `localePrefix` (URLs) or `localeLangTag` (language values).

## hreflang and `xDefaultLocale`

The page head (`LayoutBase`) and `/sitemap.xml` emit the same hreflang cluster for a page. Both get it from `routing().hreflangCluster(record)`.

- One entry per configured locale the page has a slug in, the page's own locale included, in the order of `locales`.
- Value = `localeLangTag(locale)`; URL = `resolveRecordUrl(record, locale)`.
- A page with a slug in only one locale emits no hreflang.
- Canonical: self-referencing on every page, unchanged.

`xDefaultLocale` is opt-in. When set, a page that has a version in that locale (and in at least one other) also emits `hreflang="x-default"` pointing at that locale's URL, the home page included (`/en`, not `/`). A page without a version in that locale emits no `x-default`; there is no fallback to another locale. Without the option, no `x-default` is emitted.

```ts
i18n: {
  locales: ['de_CH', 'fr_CH', 'en', 'de_DE'],
  defaultLocale: 'en',
  routingStrategy: 'prefix-always',
  localePrefix: 'locale',
  xDefaultLocale: 'en',
}
```

```html
<link rel="canonical" href="https://example.com/de-ch/about" />
<link rel="alternate" hreflang="de-CH" href="https://example.com/de-ch/about" />
<link rel="alternate" hreflang="en" href="https://example.com/en/about" />
<link rel="alternate" hreflang="de-DE" href="https://example.com/de-de/about" />
<link rel="alternate" hreflang="x-default" href="https://example.com/en/about" />
```

### Behaviour changes without an option

These reach every project on upgrade:

- **noindex pages emit no hreflang.** A page whose `_seoMetaTags` contain `<meta name="robots">` with a `noindex` directive renders its canonical and no alternates (no `x-default` either). The sitemap does not list such pages (`seo.noIndex`), as before. The `noindex` that dastro adds outside production (`dev.preventSearchIndexing` / non-production `environment`) does not remove hreflang, so previews show the production output.
- **Head and sitemap build the cluster the same way.** Before, the head listed the page's slug locales in CMS order (including locales missing from `locales`), and the sitemap listed a lone self-referencing alternate for a page that exists in one locale only. Now both follow the rules above.
